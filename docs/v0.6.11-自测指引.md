## 🚨 红线（每次开测前默读一遍）

1. **平台侧只允许点「提交前校验（不发送）」** —— 该按钮会真实进入视频模式、写提示词、设参数、上传参考图，然后在**点击发送前停下**：不产生任务记录、不消耗额度。
2. **禁止真实点击「生成视频」**（含 `Ctrl+Enter` 确认后的二次确认弹窗——一律点「取消」）。凡涉及真实出片的用例，一律标「跳过」。
3. 不要为了测试去改账号登录态、不要删除正式账号数据、不要动正在运行的旧版本程序。

## 一、测试前置准备（先备份，避免污染）

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 关闭正在运行的旧版程序 | 避免旧版占用/写入数据目录 |
| 2 | **备份旧数据**：把旧版目录下的 `isolated-data` 整个复制一份到 `isolated-data-backup-<日期>` | 出问题可一键回滚；**不要删除原目录** |
| 3 | 解压 `澜川Dola管理器-v0.6.11-便携版.zip` 到独立目录 | 不要解压到旧版目录里 |
| 4 | 确认新包 `isolated-data` 为空或不存在 | 保证是干净环境 |
| 5 | 启动 → 确认三处版本号为 v0.6.11（左上品牌行 / 左下角徽标 / 关于弹窗） | 版本不符直接停测并记录为「阻断」 |
| 6 | 账号：如需沿用旧账号，把备份的 `isolated-data` 复制过来；否则用 1 个测试账号登录 dola.com | 建议**只用 1 个测试账号**跑冒烟，多账号用例再补勾选 |
| 7 | **新建一个测试用大项目 + 2 条测试分集**（例如「自测项目-<日期>」） | 后续所有增删改都在测试项目里做，**不碰真实项目** |
| 8 | 记录基线：`git` 提交号、`app/version.json` 内容、数据目录路径 | 便于回溯 |

> 数据目录位置：工作台顶部「数据目录：已就绪」文字上悬停可看到完整路径（形如 `<包>\isolated-data\DoubaoAccountManager\workbench\`）。

## 三、各模块重点关注项

### ① 基础冒烟 —— 只关心「能不能用」
- **启动与数据**：版本号三处一致；账号列表能读到；工作台能打开且自动加载项目。
- **编辑闭环**：输入提示词 → 状态变「存在未保存改动」→ 约 1 秒变「草稿已保存」；**切换分集再切回，文字还在**。
- **素材闭环**：三种导入方式（按钮 / 拖拽 / Ctrl+V）都能进素材库；`@` 能唤起弹窗并插入 `@图N`；解除引用后文本里的 token 一起消失。
- **最安全的功能验证**：**「提交前校验（不发送）」× 1 次**（单账号）——看状态行是否走到「通过（未发送）」且**任务面板没有新增记录**。

### ② 边界场景 —— 只关心「数据会不会丢/被误删」
- **必测 4 条**（缺一不可）：
  - EDG-02 未保存改动弹窗的**三个按钮各点一次**（保存并切换 / 丢弃改动 / 取消）；
  - EDG-03 删除被引用素材：先确认弹窗**列全了依赖的分集名与 token**，再选「解除引用并删除」；
  - EDG-04 `projects.json` 损坏：改坏文件 → 重启 → **项目不消失**且目录里出现 `.corrupt-<时间戳>` 备份；
  - EDG-07 退出前兜底：输入后 **600 毫秒内**关掉程序 → 重启 → 提示「已恢复上次未保存的提示词」。
- **顺带确认**：EDG-06（有活跃任务时删除被拒）与 EDG-08（切项目不串写）。
- 观察点：任何一次重启后，**项目 / 分集 / 提示词 / 参数 / 素材 / 任务**六项都要在。

### ③ 交互体验 —— 只关心「提示对不对、布局乱不乱」
- 提示类：新建/重命名/删除/切换/保存都有 toast；草稿三态文案与颜色正确。
- 列表类：分集上移下移后**顶部下拉顺序同步**，且**重启后顺序还在**；批量复制出的副本含提示词+参数+素材。
- 危险类：批量删除的确认弹窗要**列出将删除的分集**；批量生成确认弹窗要写明**账号数、任务数、消耗额度**，点取消后**不得产生任务**。
- 布局类：拖分隔条、折叠面板、重启记忆；**把窗口缩到 1100px 宽**，核心按钮不截断、不横向溢出。
- 细节类：素材悬停放大；选中文字后「插入」是**替换选区**；`Ctrl+S` 立即保存；任务卡失败信息默认展开。

### ④ 批量账号与任务 —— 只关心「安全和状态」
- BAT-01：勾选第 2、3 个账号 → 重启 → 仍勾选；点「清空」→ 重启 → **仍是空选**。
- BAT-04（最重要）：手改 `tasks.json` 里某条 `"status"` 为 `"x_broken"` → 重启 → 该任务显示「需人工处理」+ `UNKNOWN_STATUS` 留痕，**且不会被自动提交**。
- BAT-03：暂停/恢复队列按钮状态互斥，摘要同步显示「队列已暂停」。
- BAT-05/06：中断、恢复查询、无结果时的下载按钮——文案要如实，不能假报成功。

## 四、发现 Bug 时怎么记（三步）

1. **先停手**：不要反复重试同一操作（避免把数据状态搅乱）；如涉及数据异常，先复制一份当前 `isolated-data` 留证。
2. **按模板记录**：使用 [`test-bug-report-template.md`](test-bug-report-template.md)，必填「复现步骤 / 预期 / 实际 / 截图 / 严重等级」。
3. **给证据**：
   - 截图：标注点击位置与异常文本（失败 toast、状态行、任务卡报错）；
   - 数据证据：相关 JSON（**脱敏**：去掉账号 id、Cookie、视频地址）；
   - 版本信息：左下角徽标版本号 + 包内 `app/version.json` 截图。

**快速简版模板**（详细版见模板文件）：

```
- Bug 编号：BUG-YYYYMMDD-序号
- 所属模块：工作台 / 素材库 / 任务队列 / 账号 / 下载 / 其他
- 严重等级：阻断 / 高 / 中 / 低
- 现象一句话：
- 复现步骤：1) … 2) … 3) …
- 预期结果：
- 实际现象：
- 再现概率：必现 / 偶发 x/N
- 截图/日志位置：
- 关联 Issue：BACKLOG-B?? / 新增
```

**严重等级怎么定**：

| 等级 | 判定标准（满足其一即是） |
|---|---|
| **阻断** | 打不开程序 / 工作台打不开 / 数据丢失或错乱 / 存在重复提交（可能扣费）风险 / 版本号不符 |
| **高** | 核心流程走不通（保存、切换、导入、校验失败）但数据未损坏；提示与行为严重不符 |
| **中** | 功能可用但结果不对（如引用错位、排序错乱）、提示缺失 |
| **低** | 文案、样式、间距、悬停等外观与体验问题 |
