# Bug 记录模板（测试缺陷单）

> **用途**：v0.6.11 本地人工自测（以及后续 v0.6.12 迭代测试）统一使用的缺陷记录格式。
> **配套**：[`v0.6.11-自测指引.md`](v0.6.11-自测指引.md)（怎么测）、[`test-workflow.md`](test-workflow.md)（发现后怎么处置）、[`backlog-issues.md`](backlog-issues.md)（已知遗留项）。
> **用法**：复制下面「一、模板」整块，新建一条记录填写；多条记录建议汇总到同一个文件（如 `docs/test-bugs-<日期>.md`）。

## 二、严重等级判定标准

| 等级 | 判定标准（满足其一即为该等级） | 处置路径（见 test-workflow.md） |
|---|---|---|
| **阻断** | 程序打不开 / 工作台打不开 / 项目或任务数据丢失、错乱 / 存在**重复提交（可能扣费）**风险 / 删除保护失效误删数据 / 版本号不符 | **立即停止测试**，优先修复，出 v0.6.11 补丁版（hotfix） |
| **高** | 核心流程走不通（保存草稿、切换项目/分集、素材导入、`@` 绑定、提交前校验失败）但**数据未损坏**；操作提示与实际行为严重不符 | 优先修复；同批修复后随补丁版或 v0.6.12 发布 |
| **中** | 功能可用但结果不正确（如引用错位、排序错乱、批量复制内容缺失）、必要提示缺失、重启后状态未按预期恢复 | 归入 backlog，进 v0.6.12 迭代 |
| **低** | 纯文案 / 样式 / 间距 / 悬停 / 快捷键提示等外观与体验问题 | 归入 backlog，可合并进 v0.6.12 的 UI 打磨 |

> 判定有争议时**就高不就低**，并在「影响与处置建议」中说明理由。

---

## 三、填写要求（避免无效单）

1. **可复现**：至少给出 3 步以内的操作路径；偶发问题请写「x/N 次」与当时的额外条件（例如「连续快速切换 5 次后出现」）。
2. **可定位**：必须附版本号（左下角徽标）与「预期 / 实际」对照；涉及任务状态请附任务卡的「调试信息·提交步骤」文本。
3. **可脱敏**：**严禁**把账号 id、Cookie、登录态、视频直链、真实素材原图贴进单据；数据文件只贴相关片段。
4. **可关联**：优先检查是否命中已知遗留项 B19–B25（见 `backlog-issues.md`），命中则勾选并在现象里注明差异点，避免重复提单。
5. **一事一单**：一个 bug 一条记录；同一操作引发的多个表现合并在一条并分点列出。

## 四、填写示例（参考）

```markdown
## BUG-20260929-01

- **Bug 编号**：BUG-20260929-01
- **所属模块**：工作台-项目分集
- **严重等级**：高
- **发现版本**：v0.6.11（app/version.json: version 0.6.11 / gitCommit 3c1efdc）
- **发现人 / 日期**：张三 / 2026-09-29
- **测试用例编号**：EDG-02
- **复现步骤**：
  1. 打开工作台，在提示词框输入「测试文字A」，不等待自动保存
  2. 立即用顶部「分集」下拉切到另一条分集
  3. 在弹窗中点「保存并切换」
- **再现概率**：偶发（2/5 次）
- **前置条件**：项目下有 2 条分集；软件刚启动未做过其它操作
- **预期结果**：切换成功；回到原分集时「测试文字A」仍在
- **实际现象**：切换到目标分集后，状态行短暂显示「草稿保存中…」后变为「草稿已保存」，但回到原分集时文字为空
- **截图 / 日志位置**：`shot-20260929-01.png`（状态行文案）；数据文件：`workbench/projects/<测试项目>/project.json` 片段（已脱敏）
- **关联 Issue**：[ ] B19–B25 均不符；[x] 新增问题，建议编号 BACKLOG-B26
- **影响与处置建议**：偶发但可能丢输入，建议按「高」优先修复；如定位为 600ms 防抖窗口问题，需补一条断言
```
