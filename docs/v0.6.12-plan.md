# 澜川Dola管理器 v0.6.12 · 版本规划

- **版本号**：v0.6.12（语义化版本；`app/version.json` 为唯一版本源）
- **上一版本**：v0.6.11（数据安全与额度安全专项 + 工作台体验优化；代码提交 `2b1459c`，文档提交 `3c1efdc`）
- **版本目标（一句话）**：**低风险遗留问题修复 + 小幅 UI 细节打磨**，不改架构、不换框架、不动数据模型、不触碰已验收的三条业务红线。
- **工期口径**：本文以「阶段顺序 + 工作量等级（XS/S/M）」表达排期，**不承诺日历工期**；每阶段完成即验收，未过验收不进入下一阶段。

---

## 一、版本范围

### 1.1 必做：遗留问题修复（B19–B25，全部纳入）

> 详细描述、影响范围与验收标准见 [`docs/backlog-issues.md`](backlog-issues.md)。建议按「先易后难、先可离线验证」的顺序推进。

| 顺序 | Issue | 内容 | 工作量 | 依赖 |
|---|---|---|---|---|
| 1 | BACKLOG-B22 | 自动重试退避语义修正（第 1 次 8s、第 2 次 16s） | XS | 无 |
| 2 | BACKLOG-B21 | `cancel()` pending 分支改有限重试（最多 2 次） | XS | 无 |
| 3 | BACKLOG-B20 | 驱动步骤写库失败计数可见化（不再静默吞） | XS–S | 无 |
| 4 | BACKLOG-B25 | IPC 错误协议：保留 `code`，前端 1–2 处示范分流 | S | 需先定协议（见 §3 风险） |
| 5 | BACKLOG-B23 | `library.templates` 白名单归一化 + 条数上限 | S | 无 |
| 6 | BACKLOG-B24 | 索引非法条目「忽略但上报」，界面提示 + 重建入口 | S | 复用 B3 重建通道 |
| 7 | BACKLOG-B19 | 提交结果**只读**反查骨架（读证据、不启用自动判定） | M | 需真实页面证据，允许只完成骨架并标注「待真实链路启用」 |

**共同约束（红线，任一违反即回退该条改动）**：
1. 只有 `pending` 才可提交；2. 未知状态一律转「需人工处理」；3. 下载失败绝不改变生成结果状态。

### 1.2 小幅 UI 细节打磨（低风险增量，均不改业务逻辑）

> 选型标准：只加展示与可达性，不新增业务分支；每条都必须在 1100px 窗口下不溢出。

| 编号 | 打磨点 | 现状问题 | 做法 | 工作量 |
|---|---|---|---|---|
| UI-1 | 分集列表过滤框 | 分集较多（>20 条）时只能滚动查找 | 列表工具栏加名称/提示词关键字过滤（纯前端过滤，不改变排序与选中） | XS |
| UI-2 | 任务筛选补「下载中」 | 生成成功但下载进行中的任务混在「已生成」里 | 过滤按钮组增加「下载中」项，按 `download.status` 过滤并给出计数 | XS |
| UI-3 | 空态直达按钮 | 素材库/任务列表空态只有一句话 | 空态加按钮：「导入图片」「新建分集」直达对应操作 | XS |
| UI-4 | 快捷键补全 | 仅有 Ctrl+Enter / Ctrl+S | 增加 `Esc` 关闭当前弹窗、`Ctrl+Alt+A` 打开素材插入面板（与 `@` 行为一致） | XS |
| UI-5 | 提示词统计 | 无法直观了解长度（平台对超长提示词有风险） | 编辑区右下角显示「字数 / 行数」，超阈值时变为提示色（仅提示，不阻断） | XS |
| UI-6 | 关于弹窗「已知限制」 | 版本弹窗只有更新摘要 | 增加一段固定「已知限制」（与 RELEASE.md 未验证项同步） | XS |

**合计工作量**：约 1 个 `S`（分散在 6 处小改动）。

### 1.3 明确不做（防范围蔓延）

- ❌ 不更换 UI 框架、不重写三栏布局、不引入第三方依赖
- ❌ 不改数据模型与存储 schema（除 B23/B24 的「归一化/上报」，均为向后兼容的宽松读取）
- ❌ 不改 `app/src/main.jsc`（厂商字节码）与 `runtime-resolver` 保护机制
- ❌ 不做「真实生成/下载」的自动化线上验证（需真实额度，保持【阶段2未验收】口径）
- ❌ 不新增任何外部网络请求

## 三、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| B19 反查要有真实页面证据，离线无法完整验证 | 可能只完成骨架 | 明确允许「只读骨架 + 待真实链路启用」，不为了「做完」而猜测页面结构；未启用前行为与 v0.6.11 完全一致 |
| B25 改错误协议可能影响前端文案 | 用户可见文案回归 | 协议只做「附加」，用户可见文字保持不变；仅 1–2 处按 code 分流作为示范 |
| B23/B24 涉及读取路径，改错可能影响项目可见性 | 数据不可见 | 严格保持向后兼容：缺失字段补默认、非法条目只忽略并上报；改动后必须跑「索引损坏重建」「并发读写」既有断言 |
| UI 增量与既有 CSS 冲突 | 布局回归 | CSS 只增量追加（沿用 v0.6.11 做法），不改既有选择器；以 1100/1280/1440 三档目视核对 |
| 打包 zip 中文名编码 | 解压乱码 | 沿用 v0.6.11 的 UTF-8 + EFS 写法（不使用 Windows `tar.exe` 直接产 zip），打包后解压字节复核 |
| 范围蔓延 | 迭代失控 | 严格按 §1.3「不做清单」执行；新需求一律进 backlog 下一个版本 |

## 四、版本号与发布约定

1. **版本源唯一**：只改 `app/version.json` 的 `version`（`0.6.12`）、`notes`（本轮摘要）、`history`（把 0.6.11 的 notes 归档进去）。
2. **构建戳**：`buildAt / buildChannel / gitCommit` 由打包脚本写入包内副本，**源码文件保持干净**。
3. **命名统一**：便携版目录与压缩包统一 `澜川Dola管理器-v0.6.12-便携版`；`使用说明.txt` 同步更新为 v0.6.12。
4. **发布文档**：`RELEASE.md` 增加 v0.6.12 章节；`docs/v0.6.12-手动测试用例.md` 按本轮新增点补充用例。
5. **交付目录**：`_build-v0.6.12\`（程序目录 + zip + 打包清单 + 逐文件 SHA256），与 v0.6.11 保持一致结构。
