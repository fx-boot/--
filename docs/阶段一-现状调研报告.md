## 6. 静态风险点清单（仅代码层面）

### 6.1 数据丢失类（高）

| # | 位置 | 根因 |
|---|---|---|
| R1 | `store:218-225` | `readJson` 静默吞掉 `JSON.parse` 异常并返回 fallback，`projects.json` / `project.json` 损坏后**无备份**，下一次写即永久覆盖 |
| R2 | `assets:43-46` | `readCatalog` 损坏时返回空数组，随后任何写入把 `assets.json` 覆盖为「仅含新素材」，**素材索引静默丢失**（文件仍在磁盘） |
| R3 | `store:324-330` | `saveProject` 为整份覆盖写、**无读改写**（仅 `updateProject` 有），并发/导入路径可能回退覆盖 |
| R4 | `assets:285-296` | `remove` 先 `unlink` 文件再写 catalog；若写 catalog 失败则**文件已删而索引仍在**（残留悬空引用） |

## 8. 调研结论摘要

1. **UI 已换代**：浅色「雾白·海青」三栏工作台；三栏比例 264/弹性/348，**分隔条拖拽 + 宽度本地记忆 + 折叠全部保留且工作正常**。
2. **数据模型已换代**：大项目 → 分集（`parentId`）/ 公共素材；分镜降级为「每分集一个草稿」，仅数据层保留。
3. **工程成熟度显著提升**：项目级串行读改写、原子写唯一临时名、素材写串行、任务状态机幂等、下载来源不回退、重启恢复——v0.4.0 时期我修复的多数缺陷在此版本已系统性重构。
4. **IPC 完全自洽**：54 个通道双向零差异。
5. **真实待修问题集中在**：**数据损坏无兜底**（R1/R2/R4/R27）、**状态机非法迁移被吞**（R5）、**轮询无上限空转**（R6）、**下载校验降级**（R11–R14）、**任务无清理入口**（R23）、**缺少二次确认与草稿状态**（R24–R26）。
