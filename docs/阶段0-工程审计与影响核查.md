## 2. 技术栈、入口、构建与打包

- 技术栈：Electron 桌面应用（`protection-manifest.json` 记录 `electronVersion: 43.2.0`），无前端框架，原生 HTML/CSS/JS。
- 运行依赖只有两个：`bytenode ^1.6.0`、`ffmpeg-static 5.3.0`（`app/package.json`）。
- **入口**：`app/package.json` → `main: "src/main.js"`。
- `src/main.js`（1568 字节）**只是一个加载器**：校验 `src/main.jsc` 的 sha256 后，`require("bytenode")` 再 `require("main.jsc")`。
- **打包流程不是 Electron 重新构建**，而是 **asar 覆盖式打包**：
  1. 从已发布包取原始 `app.asar` 作为基线（`_豆包开发\build.cjs` 的 `initialize()` 把它解到 `app/`）；
  2. 修改 `app/` 内的可读模块；
  3. 重新生成 `resources/app.asar`；
  4. 修补 exe 中的 asar 完整性标记。
- 项目内已用 `tools/pack-app.cjs` 复刻并加固了第 3 步，见第 6 节。

### 2.1 asar 完整性机制（实测，勿再重复推导）

- 已发布 `app.asar` 的索引中**没有逐文件 `integrity` 字段**（184 条目全部无）。
- exe 中存在标记 `[{"file":"resources\\app.asar","alg":"SHA256","value":"…"}]`，其值 = `sha256(原始 JSON 头部字节 [16, 16+jsonLength))`。
- 该标记的值指向 **`app.asar.orig`（改动前）** 的头部；`豆包管理器.exe` 与 `豆包管理器.exe.orig` 的标记**完全相同**（两文件仅 1 字节差异，位于偏移 181442582，与标记无关）。
- 而实际运行使用的是**被替换过的** `app.asar`。**因此该完整性保险丝未启用**，重打包无需改 exe。
  `tools/pack-app.cjs` 默认不写 exe；如将来需要，`--patch-exe` 会按上面已验证的公式回写。

## 4. 关键源码缺失说明

**缺失**：`src/main.jsc` 与 `renderer/app.js` 的人类可读源码。

**影响**：无法以"重新构建整个产品"的方式开发；无法直接调用或被调用其内部的账号/会话/提交函数。

**可维护的增量接入方案**（本项目采用）：

- 不反编译、不改动这两个文件；
- 新功能一律做成独立模块，通过第 3.3 节的挂接点接入；
- 需要"账号 + 独立会话 + 平台操作"时，走 **独立 webview/BrowserWindow + 既有 `persist:doubao-manager-<accountId>` 分区**，配合 `webview-debugger-broker`/`webContents.debugger` 自行驱动平台页面；
- 需要账号元数据时走既有 `accounts:list` IPC，不自行读取/改写其存储格式。

因此本工作台的"平台适配层"是**独立实现**，与 main.jsc 内部逻辑解耦，但共享同一份登录会话（这是"复用现有独立登录会话"的正确做法）。

## 6. 打包工具缺陷与修复（本次审计发现）

### 6.1 缺陷

`tools/pack-app.cjs` 初版的 `buildArchive` 先用 `stat` 的**原始文件大小**分配 asar 偏移，之后才改写 `package.json` 的 `main`。`main` 变短后，`package.json` **之后**所有文件的偏移全部错位，内容被读串。

### 6.2 证据

对带入口注入的 dev 包与 `app/` 逐字节比对：**53 个文件内容不一致**，覆盖 `protection-manifest.json`、全部 `renderer/*`、全部 `src/*`（含 `main.js`、`main.jsc`）。
包内探针脚本头部被截断（包内 6292 字节 vs 源 6337 字节），首行为 `*`，属非法 JS。

该缺陷只影响"注入入口"模式；不带 `--entry/--entry-file` 的普通打包偏移一致，故早前的基线往返校验（184/184）能通过——**这也是该缺陷当时未被发现的原因**。

### 6.3 修复与防护

- 改为"先读取并按需改写内容 → 再用改写后的真实长度分配偏移"。
- 新增**结构自检** `verifyArchive`：落盘前把 asar 重新解析，逐条目与源字节比对，并校验 `base` 与头部对齐长度一致；任一不符即失败，不产出坏包。
- 修复后：自检 **186 条目全部通过**；与 `app/` 比对 **183/184 一致**，仅两项预期差异（`package.json` 因注入入口而改写、`boot-probe.cjs` 为注入项）。
