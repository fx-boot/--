# v0.6.11 自测 Bug 总清单（Bug Tracker）

> **用途**：v0.6.11 本地人工自测阶段发现的全部 Bug 的**统一入口与总台账**，一屏看清「有哪些 Bug、什么等级、修没修、哪一版解决」。
> **配套文档**：[`test-bug-report-template.md`](test-bug-report-template.md)（缺陷单模板）、[`test-workflow.md`](test-workflow.md)（分流与复测口径）、[`hotfix-build-rule.md`](hotfix-build-rule.md)（补丁打包规范）、[`backlog-issues.md`](backlog-issues.md)（已知遗留项 B19–B25）、[`git-branch-guide.md`](git-branch-guide.md)（分支与 tag 规范）。

---

## 一、录入规则（自动执行）

1. 测试人发现 Bug 后，按 [`test-bug-report-template.md`](test-bug-report-template.md) 模板填写缺陷单（编号格式 `BUG-YYYYMMDD-序号`，如 `BUG-20260929-01`），提交给助手。
2. 助手收到缺陷单后**自动在下方总清单追加一行**，并做两项核查：
   - 是否命中已知遗留项 **BACKLOG-B19～B25**：命中则在「关联Issue」列填写对应 BACKLOG 编号，不新开 backlog 编号；
   - 严重等级复核（阻断 / 高 / 中 / 低，争议时**就高不就低**）。
3. 后续每次状态变化（待复现 → 修复中 → 已修复 → 关闭）助手同步更新该行；一张缺陷单的详细复现步骤、截图、日志仍保存在缺陷单原文中，本清单只做索引。
4. **分流规则**（详见 [`test-workflow.md`](test-workflow.md)）：
   - **阻断 / 高**：走 hotfix 补丁流程（从 tag `v0.6.11` 切分支，发补丁版 `v0.6.11.1`，必要时 `.2`），目标版本填补丁版本号；
   - **中 / 低**：不做 hotfix，录入 [`backlog-issues.md`](backlog-issues.md)（编号从 `BACKLOG-B26` 起），目标版本填 **v0.6.12**。

### 状态口径

| 状态 | 含义 |
|---|---|
| 待复现 | 缺陷单已录入，尚未按步骤复现/等级复核未完成 |
| 修复中 | 已确认并进入修复（hotfix 分支或 backlog 排期） |
| 已修复 | 代码已修复、离线断言已入库且全绿；**等待原提单人复测** |
| 关闭 | 原提单人复测通过，且修复已提交（发布补丁的还需已打 tag） |

> 关闭条件（三者齐全）：① 缺陷单「复测结论：通过」；② 对应离线断言全绿；③ 修复已提交（发布版已打 tag）。复测未通过不得关闭，连续两次修复未通过升级为「阻断」。
